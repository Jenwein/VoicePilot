### **核心设计思想：引入“多轮对话”循环**

我们将放弃目前“C++ 调用 Python 理解 \-\> C++ 执行 \-\> C++ 调用 Python 生成回复”的固定三步流程。取而代之的是，在 C++ 的 AgentCore 中引入一个循环。在这个循环里，C++ 不断地将用户的请求和工具的执行结果反馈给 Python 端的 Gemini API，让大模型根据当前的“对话历史”来决定下一步是继续调用其他工具，还是生成最终答复。

---

### **第一阶段：Python 端 (ai\_service.py) 的逻辑重构**

Python 脚本将不再有 understand 和 generate\_response 两个独立的子命令，而是统一为一个，例如 process\_turn (处理一轮对话)。这个函数将负责与 Gemini API 的所有交互。

1. **统一入口函数 handle\_process\_turn：**  
   * **输入参数**:  
     * \--tool\_definitions\_path: 工具定义的 JSON 文件路径 (与之前相同)。  
     * \--user\_input\_audio\_path (可选): 仅在第一轮对话时提供用户的录音文件。  
     * \--tool\_results\_json (可选): 在后续对话轮次中，提供上一轮工具执行的结果。  
   * **核心逻辑**:  
     1. **构建对话历史 contents**:  
        * **第一轮**: contents 包含一个引导性的 prompt 和用户上传的音频文件 (audio\_file)。  
        * **后续轮次**: contents 除了包含引导 prompt，还需包含之前所有轮次的**模型回复(即函数调用请求)和开发者提供的工具执行结果**。这对于模型理解上下文至关重要。  
     2. **调用 Gemini API generate\_content**: 将构建好的 contents 和 tools 配置发送给模型。  
     3. **解析模型响应**:  
        * **情况A：模型需要调用工具**: 如果响应中包含 function\_call，将其格式化为统一的 JSON 格式（即使只有一个，也用数组），然后 print 输出给 C++。  
        * **情况B：模型认为任务完成**: 如果响应中不包含 function\_call，而是直接的文本回复（response.text），这说明模型认为所有步骤都已完成。将这个文本包装在一个 JSON 对象中 print 输出，标志着对话循环的结束。

---

### **第二阶段：C++ 端 (AgentCore.cpp) 的逻辑重构**

C++ 将成为整个流程的主导者，负责驱动与 Python 的循环通信，并执行本地工具。

1. **重构 ProcessAudio 函数为循环模式：**  
   * **初始化**: 创建一个空的 std::vector\<nlohmann::json\> tool\_results 用于存储每一轮的工具执行结果。  
   * **启动循环 (do-while)**:  
     1. **构建 Python 命令**:  
        * **首次循环**: 调用 ai\_service.py process\_turn，并传递 \--user\_input\_audio\_path 参数。  
        * **后续循环**: 调用 ai\_service.py process\_turn，并传递 \--tool\_results\_json 参数，其值为上一轮 tool\_results 序列化后的 JSON 字符串。  
     2. **执行命令并获取 Python 输出**。  
     3. **解析 Python 返回的 JSON**:  
        * **如果包含 tool\_calls 字段**:  
          * 清空上一轮的 tool\_results。  
          * 遍历 tool\_calls 数组中的每一个工具调用请求。  
          * 通过 ToolRegistry::ExecuteTool 执行该工具。  
          * 将工具名和执行结果（一个包含 name 和 result 的 JSON 对象）存入 tool\_results 中。  
          * 设置循环继续的标志位为 true。  
        * **如果包含 final\_response 字段**:  
          * 获取该字段的文本内容。  
          * 调用 GenerateAndSpeakResponse() 函数，将此文本作为最终结果进行播报。  
          * 设置循环继续的标志位为 false，退出循环。  
        * **如果包含 error 字段**:  
          * 处理错误（例如，直接播报错误信息）。  
          * 设置循环继续的标志位为 false，退出循环。  
   * **循环结束条件**: 当从 Python 端接收到 final\_response 或 error 时，循环结束。

---

### **第三阶段：两端通信的 JSON 格式优化**

为了支持新的循环逻辑，我们需要清晰、统一的 JSON 通信格式。

1. **Python \-\> C++ (模型决策结果)**:  
   * **请求调用工具时**:  
     JSON  
     {  
       "tool\_calls": \[  
         {  
           "name": "get\_current\_time",  
           "args": {}  
         },  
         {  
           "name": "get\_known\_folder\_path",  
           "args": { "folder\_name": "desktop" }  
         }  
       \]  
     }

   * **给出最终答复时**:  
     JSON  
     {  
       "final\_response": "任务已完成，当前时间已保存到您的桌面文件中。"  
     }

2. **C++ \-\> Python (工具执行结果)**:  
   * 作为 \--tool\_results\_json 参数的值（一个 JSON 字符串）:  
     JSON  
     \[  
       {  
         "tool\_name": "get\_current\_time",  
         "content": "Success: Current time is 2025-10-22 10:30:00"  
       },  
       {  
         "tool\_name": "get\_known\_folder\_path",  
         "content": "Success: C:/Users/YourUser/Desktop"  
       }  
     \]

### **示例流程：“获取当前时间，写入桌面文件”**

1. **第 1 轮 (C++ \-\> Python \-\> C++)**:  
   * **C++** 调用 process\_turn \--user\_input\_audio\_path ...。  
   * **Python** 将音频发给 Gemini。Gemini 分析后认为需要并行执行两个工具，返回 tool\_calls，包含 get\_current\_time 和 get\_known\_folder\_path。  
   * **C++** 收到 JSON，在本地执行这两个工具，得到时间和桌面路径，并存入 tool\_results。  
2. **第 2 轮 (C++ \-\> Python \-\> C++)**:  
   * **C++** 发现 tool\_results 不为空，再次进入循环，调用 process\_turn \--tool\_results\_json "..."，将上一步的结果传给 Python。  
   * **Python** 将用户的原始请求、第一次的工具调用请求、以及两个工具的执行结果一起发给 Gemini。Gemini 看到现在信息齐全了，于是返回 tool\_calls，包含 write\_to\_file，并利用之前的结果填充了 path 和 content 参数。  
   * **C++** 收到 JSON，执行 write\_to\_file 工具，将文件写入桌面。  
3. **第 3 轮 (C++ \-\> Python \-\> C++)**:  
   * **C++** 再次进入循环，将 write\_to\_file 的成功结果传给 Python。  
   * **Python** 将包含所有历史记录的对话发给 Gemini。Gemini 判断所有任务已完成，不再调用工具，而是直接生成一句总结性的回复。  
   * **Python** 返回 final\_response JSON。  
4. **结束**:  
   * **C++** 收到 final\_response，退出循环，将文本送去 TTS 模块播报，流程结束。
